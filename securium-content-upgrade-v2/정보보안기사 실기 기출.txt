14. 도스(DoS) 공격 원리 관련 문제
(A) Land Attack : 출발지 IP 주소를 목적지 IP 주소(대상 시스템의 IP 주소)와 동일하게 위조한 패킷을 전송하여, 대상 시스템이 자기 자신에게 응답을 보내는 비정상 동작을 유
발함으로써 무한 루프(loop) 상태 또는 과도한 자원 소모를 일으키는 서비스 거부 공격이다.
(B) Smurf Attack : 출발지 IP를 희생자(Target) IP로 위조(IP 스푸핑)한 후 증폭(반사) 네트워크의 다이렉티드 브로드캐스트(Directed Broadcast) 주소로 ICMP Echo
Request 패킷을 전송함으로써, 해당 네트워크의 모든 호스트가 ICMP Echo Reply 패킷을 희생자에게 보내도록 만들어 네트워크 대역폭을 소진시키는 서비스 거부 공격이다.

18. 특수 권한(SUID/SGID) 관련 문제
1) SUID 설정 시 발생 위협
SUID가 설정된 실행 파일은 실행 시 일반 사용자가 파일 소유자(예: root)의 권한으로 실행된다. 따라서 보안 취약점이 있는 root 소유의 실행 파일에 불필요하게 SUID가 설정
될 경우, 권한이 없는 사용자가 root 권한을 획득(권한 상승)하는 위협이 존재한다.
2) SGID 설정 시 발생 위협
SGID가 설정된 실행 파일은 실행 시 일반 사용자가 파일 소유 그룹의 권한으로 실행된다. 따라서 보안 취약점이 있는 root 소유그룹의 실행 파일에 불필요하게 SGID가 설정될
경우, 권한이 없는 사용자가 root 소유그룹의 권한을 획득(권한 상승)하는 위협이 존재한다.
3) SUID/SGID 제거 명령어
chmod -s <파일명> ( chmod a-s <파일명> 과 동일함)
(또는) chmod ug-s <파일명>
(또는) chmod u-s,g-s <파일명>
(또는) SUID 제거 : chmod u-s <파일명>, SGID 제거 : chmod g-s <파일명>
4) SUID 검색 명령 : find / -perm -( )
4000
5) SGID 검색 명령 : find / -perm -( )
2000

16. SSL/TLS에서 비대칭키/대칭키 암호의 사용 단계와 용도 관련 문제
(A) 비대칭키(공개키) 암호 방식
1. 서버 인증(Server Certificate) 단계 : 서버가 전달한 인증서를 클라이언트가 인증기관(CA)의 공개키로 검증하여 서버 인증(서버 신원확인)을 수행하는 데 사용한다.
2. 키 교환(Server Key Exchange, Client Key Exchange) 단계 : 다양한 키(세션키, 비밀키, IV 등) 생성에 필요한 사전 마스터 비밀(Premaster Secret)을 생성 및 공유하
기 위해 사용한다.
- RSA 방식 : 클라이언트는 사전 마스터 비밀 생성 후 수신한 서버 인증서에 포함된 서버 공개키로 암호화하여 서버에 전달
- Diffie-Hellman 방식 : 서버와 클라이언트는 각각 DH 공개값(공개 매개변수, 공개키)을 교환한 후, 자신의 개인키와 상대방의 공개키를 이용하여 각자 사전 마스터 비밀을 계
산한다.
(B) 대칭키 암호 방식
1. 암호화 통신 단계(Change Cipher Spec 이후 단계) : 핸드셰이크(협상) 과정에서 생성된 세션키와 초기화 벡터(IV)를 사용하여 송수신 메시지를 암호화하기 위해 사용한다.
