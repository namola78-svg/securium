# SECURIUM 전체 콘텐츠 전수 변환 작업

## 목표
첨부된 `2026 정보보안기사 올인원_구매인증 이벤트 자료.pdf`와 `정보보안기사 실기 기출.txt`의 이론·필기·실기를 모두 분석하되 원문을 그대로 서비스에 복사하지 않는다. `data/source-inventory.json`에 잡힌 항목을 작업 큐로 사용하고, SECURIUM의 기존 콘텐츠와 비교하여 이론을 개선하고 필기/실기 문제는 독립적인 신규 문항으로 재설계한다.

## 반드시 먼저 할 일
1. 현재 저장소의 schema, migrations, seed, content repository, question type, curriculum/ontology 모델을 읽는다.
2. 기존 정보보안기사 과정/과목/주제/lesson/question 데이터를 조사한다.
3. 이 패키지의 JSON을 현재 schema에 억지로 맞추지 말고, 필요한 import adapter를 별도로 만든다.
4. 원천파일을 공개 정적 파일이나 사용자 다운로드 경로에 복사하지 않는다.

## 이론 처리
각 THEORY 항목을 기존 SECURIUM 이론과 비교한다. 기존 설명을 보존할 가치가 있으면 통합하고, 부족한 부분만 보강한다. 결과는 최소 다음을 포함한다: 학습목표, 개념 개요, 핵심 포인트, 비교/혼동 포인트, 실무 사례, 시험 포인트, 관련 개념. 원문 문장을 길게 재사용하지 않는다. 출처가 오래되거나 법·표준의 최신성이 중요한 항목은 자동 확정하지 말고 `needs_verification=true`로 둔다.

## 필기 300문항 처리
각 WRITTEN 항목은 원문 문제의 `평가 개념 / 난이도 / 오답 유도 방식 / 필요한 사고과정`만 추출한다. 다음은 금지한다: 원문 문장 복사, 보기 순서만 변경, 고유명사만 변경, 숫자만 변경, 부정/긍정형만 뒤집기. 새로운 문제는 새 시나리오·비교·판단·적용 중 하나 이상의 새로운 추론 요소를 가져야 한다. 기존 문제은행과 의미 중복도 검사 후 DRAFT로 저장한다.

## 실기 처리
PDF 3회 실기와 TXT 전체를 함께 사용한다. 중복된 출제개념은 하나의 concept cluster로 묶는다. 단답형은 단순 암기만 반복하지 말고 일부를 상황형으로 확장한다. 로그/설정/코드/계산/서술 문제는 원 자료의 로그·IP·코드·조직명·수치를 그대로 쓰지 말고 새 데이터를 설계한다. 답안은 채점 포인트와 해설을 별도로 저장한다.

## 문제 생성 목표
- 원천 1문항당 기계적으로 1문항을 만들 필요는 없다.
- 핵심 개념은 Level 1~5 중 필요한 난이도로 확장한다.
- 의미 없는 유사문제 대량생성을 금지한다.
- 가능하면 필기 개념과 실기 적용문제를 같은 ontology concept에 연결한다.

## 원문 유사도 차단
`content-policy.ts`의 정책을 적용하고, 원천 문자열과 후보 문제 사이 lexical similarity뿐 아니라 구조적 유사성도 점검한다. 다음 패턴은 강제 재생성한다.
- 선택지만 재배열
- 숫자/IP/인물/회사명만 교체
- 같은 로그 형식에 값만 교체
- 문장 순서만 변경
- 질문형을 서술형으로만 변경

## 온톨로지 연결
가능한 경우 `과정 → 과목 → 주제 → LearningUnit/Lesson → concept → question → explanation` 관계로 연결한다. 동일 concept가 필기와 실기에 반복되면 새 concept를 중복 생성하지 않는다. 선행개념/관련개념/혼동개념 관계를 활용한다.

## 등록 안전장치
- 모든 새 콘텐츠는 최초 `DRAFT`.
- 기존 published 콘텐츠를 무조건 overwrite하지 않는다.
- provenance에는 원천 파일명, source_id, 처리 버전, 생성시각, review 상태만 남기고 원문 전체를 저장하지 않는다.
- 법령·규정·표준·제품 버전처럼 변할 수 있는 사실은 검증 플래그를 둔다.

## 완료 기준
1. `source-inventory.json`의 모든 항목이 `PROCESSED`, `MERGED_AS_DUPLICATE`, `NEEDS_VERIFICATION`, `SKIPPED_WITH_REASON` 중 하나의 상태를 갖는다.
2. 원천 문항 복제 검사가 통과한다.
3. 기존 문제은행 의미중복 검사가 통과한다.
4. typecheck, lint, unit/integration tests, production build가 통과한다.
5. 실행 결과를 `docs/content-import-report.md`에 작성한다. 보고서에는 처리 건수, 병합 건수, 검증 필요 건수, 신규 이론/필기/실기 수, 중복 차단 수를 기록한다.

## 금지
테스트 통과를 위해 검증을 삭제하거나, 문제를 비공개로 숨겨 수치만 맞추거나, source 문장을 그대로 DB에 넣는 방식으로 완료 처리하지 않는다.
