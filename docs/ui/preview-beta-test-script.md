# Preview Beta Test Script

This script is for guided SECURIUM Preview Beta sessions. It should be used with a facilitator so that feedback captures trust, clarity, and next-action comprehension rather than only visual preference.

## Session setup

- Duration: 30-45 minutes.
- Environment: `https://securium.vercel.app`.
- Account: use a prepared learner or admin test account.
- Recording: optional, only with participant consent.
- Do not ask participants to enter secrets, private credentials, or real exam content.

## Opening script

SECURIUM is an AI-assisted learning platform for information security and privacy protection professionals. This session is not a test of you. We are checking whether the product makes the next learning or admin action clear.

Please think aloud while using the product:

- What do you expect this screen to do?
- What would you click next?
- What feels trustworthy or confusing?
- Which labels feel too technical?

## Learner flow

| Step | Task | Success signal |
| --- | --- | --- |
| 1 | Open the home page and explain what SECURIUM is. | Participant can describe the product purpose in their own words. |
| 2 | Find a course that matches a certification goal. | Participant can compare courses without asking what each card means. |
| 3 | Open a course and decide whether to start it. | Participant understands course audience, content amount, and CTA state. |
| 4 | Open the learner dashboard. | Participant identifies the next recommended action within 10 seconds. |
| 5 | Open the curriculum for 정보보안기사. | Participant understands the official curriculum path and CourseLesson progress area. |
| 6 | Find where to practice questions. | Participant reaches practice without confusion between course and global practice. |
| 7 | Open AI Tutor or an AI explanation area. | Participant understands AI output is reference-only and should be checked against sources. |
| 8 | Open wrong notes or today's review. | Participant understands empty state or review priority. |
| 9 | Open analytics. | Participant can explain what the current progress and sparse data state mean. |

## Admin flow

| Step | Task | Success signal |
| --- | --- | --- |
| 1 | Open the admin dashboard. | Participant understands the Console Shell and main navigation. |
| 2 | Open Curriculum. | Participant can find official title, stable key, source metadata, and inspector. |
| 3 | Open Coverage. | Participant understands gap queue and coverage priority. |
| 4 | Open Ontology. | Participant can identify concept, alias, relation, and review state. |
| 5 | Open AI Explainability. | Participant can explain query expansion, retrieval context, citations, and safety notes. |
| 6 | Open Content Revisions. | Participant understands version, impact, and publication state. |
| 7 | Open Question Reports. | Participant understands report queue and inspector detail. |

## Facilitator checklist

- [ ] Participant can explain the product value.
- [ ] Participant can find the next learning action.
- [ ] Participant does not mistake AI content for official scoring.
- [ ] Participant understands official curriculum source metadata.
- [ ] Participant can navigate back from detail/inspector states.
- [ ] Participant can use the product at mobile width if tested.
- [ ] Participant notices no internal development language on public screens.
