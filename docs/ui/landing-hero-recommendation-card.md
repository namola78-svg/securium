# Landing Hero Recommendation Card

## 기존 문제

공개 랜딩 Hero의 오른쪽 카드는 `ISMS-P`, `인증기준 2.6 접근통제`, `진행률 68%`를 표시했다. 이 정보는 로그인 후 대시보드나 실제 학습 화면에서는 의미가 있지만, 첫 방문자에게는 특정 사용자의 학습 상태처럼 보일 수 있다.

특히 공개 화면에서는 사용자가 아직 SECURIUM의 제품 성격, 과정 범위, 학습 흐름을 파악하기 전이므로 세부 인증기준 번호와 진행률이 먼저 보이면 정보 위계가 어색해진다.

## 정보 위계 원칙

공개 Hero 카드에서는 다음을 우선 표시한다.

1. SECURIUM이 어떤 학습 경험을 제공하는지
2. 어떤 과정을 선택할 수 있는지
3. 공식 기준과 AI 설명이 어떻게 연결되는지
4. 사용자가 다음에 무엇을 누르면 되는지

공개 Hero 카드에서는 다음을 기본적으로 제외한다.

- 개인화된 진도율처럼 보이는 숫자
- 세부 CurriculumNode 명칭
- 인증기준 세부 번호
- 관리자 Coverage 또는 ReviewStatus
- 실제 사용자 학습 상태처럼 오해될 수 있는 정보

## 비로그인 카드

현재 공개 Home은 로그인 사용자를 `/dashboard`로 리다이렉트한다. 따라서 랜딩 Hero 카드는 비로그인 방문자용 제품 소개 카드로 유지한다.

표시 구조:

- Eyebrow: `SECURIUM 학습 경험`
- Badge: `공개 과정`
- 제목: `공식 커리큘럼부터 AI 복습까지`
- 설명: 과정 선택부터 이론, 문제, 근거 해설, 오답 복습을 하나의 흐름으로 제공
- 보조 정보:
  - 공식 기준 기반
  - 근거 기반 설명
  - 이론 · 문제 · 복습
- CTA: `과정 둘러보기`

## 로그인 카드

현재 Home은 로그인 상태에서 Hero를 렌더링하지 않고 `/dashboard`로 이동한다. 개인화된 “이어 학습” 정보는 `/dashboard`에서만 표시한다.

향후 Home에서도 로그인 Hero를 별도로 제공하려면 다음 조건을 모두 만족해야 한다.

- 서버 HTML과 클라이언트 첫 렌더의 인증 상태가 일치한다.
- 실제 최근 학습 데이터와 실제 진도율만 표시한다.
- 데이터가 없으면 개인화 카드가 아니라 일반 과정 카드로 fallback한다.
- 하드코딩된 진행률을 실제 사용자 진도처럼 표시하지 않는다.

## 진행률 정책

공개 Hero에서는 진행률 수치를 표시하지 않는다.

이유:

- 공개 방문자에게 개인화 수치처럼 보일 수 있다.
- 하드코딩된 숫자와 실제 학습 데이터의 경계가 흐려진다.
- Hero의 목적은 세부 학습 상태가 아니라 제품 가치 전달이다.

진도율은 로그인 후 대시보드, 과정 학습 개요, 학습분석 화면에서 실제 데이터 기반으로 표시한다.

## 선택 문구

최종 선택:

> 공식 커리큘럼부터 AI 복습까지

선택 이유:

- Hero 왼쪽의 “공식 기준으로 배우고 AI 근거로 이해하는 정보보호 학습 플랫폼” 메시지와 자연스럽게 연결된다.
- 특정 과정이나 세부 항목에 치우치지 않는다.
- SECURIUM의 핵심 연결 구조인 커리큘럼, 문제, AI, 복습을 짧게 설명한다.

## 반응형

- 기존 Hero grid와 panel 구조를 유지한다.
- 모바일에서는 카드가 Hero CTA 아래로 내려가며, CTA는 최소 46px 높이를 가진다.
- 메타데이터는 3개 항목으로 제한해 줄바꿈과 카드 높이 증가를 줄인다.

## 접근성

- 오른쪽 카드는 `aria-label="SECURIUM 학습 경험 요약"`을 사용한다.
- `공개 과정` 배지는 보조 상태일 뿐 색상만으로 의미를 전달하지 않는다.
- CTA는 실제 경로 `/courses`로 이동하며 accessible name은 `과정 둘러보기`이다.
- 진행률 bar를 제거했으므로 관련 `aria-label`도 함께 제거했다.

## 테스트

- 공개 Hero에 `인증기준 2.6 접근통제`와 `68%`가 노출되지 않는지 확인한다.
- 공개 Hero가 제품 가치, 공식 기준 기반, 근거 기반 설명, 이론·문제·복습 흐름을 표시하는지 확인한다.
- 타입체크, 린트, 유닛 테스트, 빌드를 수행한다.

## 후속 개선

1. 로그인 후 대시보드의 개인화 카드와 공개 Hero 카드를 시각적으로 명확히 구분한다.
2. 과정 수 표시가 0개인 경우 문구를 더 친절하게 다듬는다.
3. Landing E2E 서버 readiness 문제가 해결되면 서버 렌더 HTML 회귀 테스트를 다시 활성 검증한다.
