# 개인정보 보존 및 파기

## 정책 원칙

이 문서는 법정 보존기간을 확정하지 않는다. 운영기관은 적용 법령, 계약, 정보보호 정책과 서비스 목적을 검토해 데이터 유형별 보존기간을 설정하고 정기적으로 승인해야 한다.

현재 코드에는 모든 데이터 유형을 자동 파기하는 통합 스케줄러가 없다. 아래 내용은 운영 정책과 향후 구현 계약이며, 자동 파기가 완료된 것으로 보아서는 안 된다.

## 운영기관 설정 항목

데이터 유형별로 다음 값을 관리한다.

- 보존 시작 이벤트
- 보존 기간 또는 종료 조건
- 활성 사용자에게 필요한 최소 보존 범위
- 파기 방식: 물리 삭제, 비식별화, 익명 집계, 객체 삭제
- 법적 보존 또는 분쟁 보존 여부
- 승인자와 실행 주기
- 백업에서의 만료와 복구 시 재파기 절차
- 감사 증적에 남길 최소 메타데이터

운영 설정은 코드 상수로 고정하지 않고 승인된 환경 설정 또는 관리 데이터로 관리하는 것을 권장한다.

## 데이터별 정책 결정표

| 데이터 | 보존 시작 이벤트 예 | 파기 시 주의사항 |
|---|---|---|
| 회원정보 | 탈퇴, 계정 정지 종료 | SIWC 식별자, 이메일과 역할 관계를 분리 검토 |
| 수강·학습 기록 | 수강 취소, 탈퇴 | 과정별 통계와 자격 증명의 보존 근거 확인 |
| 문제 답안·시도 | 제출, 탈퇴 | 답안 원문과 익명 통계를 구분 |
| 오답노트·메모 | 마지막 수정, 탈퇴 | 사용자 작성 메모의 개인정보 포함 가능성 |
| 시험 결과 | 시험 종료, 탈퇴 | 이의제기 및 증명 기간을 운영기관이 결정 |
| AI 요청·결과 | 생성 시각 | 답안 원문을 로그에 저장하지 않으며 현재 `AI_RETENTION_DAYS`는 정책 입력값일 뿐 자동 파기 완료를 뜻하지 않음 |
| 강의 메모 | 마지막 수정, 탈퇴 | XSS 안전 처리와 사용자 소유권 유지 |
| 오디오·강의 재생 진도 | 마지막 재생, 탈퇴 | 서비스 제공 목적 종료 후 최소화 |
| 감사로그 | 생성 시각 | 원문 IP·비밀번호·토큰·답안 원문을 보존하지 않음 |
| 업로드 파일 | 연결 콘텐츠 삭제, 만료 | DB 참조와 객체 삭제 순서를 조정 |
| 내보내기 파일 | 생성 시각 또는 다운로드 | 짧은 만료, 접근 제한, 만료 후 객체 삭제 권장 |

## 파기 처리 흐름

1. 만료 후보를 계산하되 즉시 삭제하지 않는다.
2. 법적 보존, 분쟁, 복구, 진행 중 시험과 콘텐츠 연결을 확인한다.
3. 파기 대상을 최소 식별자와 건수로 검토·승인한다.
4. 사용자 소유 데이터와 과정별 집계의 영향을 계산한다.
5. DB와 Storage 파기를 하나의 작업 ID로 추적한다.
6. 원문을 남기지 않는 감사 이벤트에 결과와 건수만 기록한다.
7. 백업 만료 일정과 복구 시 재파기 목록을 갱신한다.
8. 샘플 검증으로 검색·API·signed URL에서 더 이상 접근되지 않는지 확인한다.

## 삭제 순서와 무결성

- 사용자의 소유 데이터를 다른 사용자의 데이터와 함께 대량 삭제하지 않는다.
- QuestionAttempt, WrongNote, MockExamAttempt 같은 학습 기록의 외래키와 통계 영향을 먼저 확인한다.
- 콘텐츠를 비활성화하거나 superseded 처리하는 것과 사용자 기록 파기를 구분한다.
- 감사로그는 일반 관리자에게 수정·삭제 API를 제공하지 않는다.
- 물리 삭제가 불가능하거나 통계 목적이 남으면 재식별이 불가능한 익명 집계로 전환할 수 있는지 별도 승인한다.
- 백업에서 복원된 만료 데이터는 파기 대기 목록을 다시 적용한다.

## 권리 요청 및 예외

사용자 요청, 계약 종료, 법적 보존 등 예외마다 확인자와 승인자를 분리한다. 내보내기에는 최소 데이터만 포함하고, 파일은 비공개 Storage에서 제한된 시간만 제공한다. 모든 예외 처리는 request ID와 정책 근거를 기록하되 개인정보 원문을 감사 metadata에 복제하지 않는다.

## 운영 전 필수 결정

- 각 데이터 유형의 실제 보존기간과 시작 이벤트
- 법적 보존 승인 절차
- 파기 작업 주기, 담당자와 이중 승인 기준
- 백업 보존기간과 복구 후 재파기 방식
- 익명화 기준과 재식별 위험 검토
- AI 로그, 감사로그, 내보내기 파일의 별도 정책
- 자동 파기 구현 전 수동 통제와 정기 검토 방법
