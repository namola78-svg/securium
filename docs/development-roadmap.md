# 정보보호·개인정보보호 통합 학습 플랫폼 개발 로드맵

작성일: 2026-07-25

## 현재 기준선

### 확인된 사실

- 현재 활성 제품 기능은 starter 로딩 화면뿐이다.
- 직접 실행한 Vinext production build는 성공했다.
- 빌드 결과 대상 Node 테스트 2개가 통과했다.
- 기본 `npm test`는 Windows에서 Unix 방식 환경변수 할당 때문에 실패한다.
- DB, 역할, 과정, 학습 기능은 아직 없다.

## 개발 원칙

### 제안사항

- 기존 빌드·배포 골격을 보존하고 작은 수직 단위로 확장한다.
- 각 단계에서 build, lint, 관련 단위/통합 테스트를 통과시킨다.
- 확인되지 않은 외부 인증과 운영 인프라를 먼저 가정하지 않는다.
- 과정별 분기 코드를 복제하지 않고 공통 학습 엔진과 데이터 구성을 분리한다.
- 보안과 접근성은 마지막 점검 항목이 아니라 각 단계의 완료 조건으로 둔다.

## 단계별 로드맵

### 0단계: 기준선 안정화

목표: 모든 개발 환경에서 동일한 검증 명령을 실행할 수 있게 한다.

작업:

- Windows 비호환 npm 스크립트 수정
- starter 빌드·테스트 기준선 보존
- `.env.example` 정책 수립
- Git 기준선과 브랜치 전략 확인
- 한국어 `lang`과 제품 메타데이터 변경 준비

완료 조건:

- `npm run build`, `npm test`, `npm run lint`가 지원 환경에서 실행됨
- 기존 starter 테스트 결과가 기록됨

### 1단계: 멀티과정 기반 골격

목표: 7개 과정을 데이터로 관리하고 URL에서 전환한다.

작업:

- D1 바인딩 결정 및 `courses`, `course_domains`, `modules` 스키마
- 7개 과정 seed
- 과정 repository/query
- `/courses`, `/courses/[courseSlug]`
- 공통 과정 전환 UI
- 404와 빈 상태
- starter 스켈레톤을 실제 제품 셸로 교체

완료 조건:

- 7개 과정이 DB에서 조회됨
- slug로 직접 접근·새로고침 가능
- 잘못된 slug가 안전하게 처리됨
- 과정 전환이 모바일·키보드 환경에서 동작
- migration, repository, route 테스트 통과

### 2단계: 신원과 권한

목표: 보호 화면과 관리자 작업의 서버 측 권한을 확립한다.

작업:

- 실제 배포 인증 방식 결정
- `users`, `roles`, `user_roles`
- 학습자 대시보드 보호
- 관리자 라우트 보호
- 정책 함수와 권한 거부 테스트
- 권한 변경 감사로그

완료 조건:

- 익명 사용자가 보호 데이터에 접근할 수 없음
- 학습자와 관리자 권한이 서버에서 분리됨
- 과정별 관리자 범위를 검증할 수 있음

### 3단계: 콘텐츠와 진도

목표: 한 과정의 학습 단위를 완료하고 기록한다.

작업:

- `learning_units`, `content_items`, `content_versions`, 과정 매핑
- 콘텐츠 목록·상세
- 등록과 진도 저장
- 대시보드 진행률
- 콘텐츠 공개 상태와 버전 고정

완료 조건:

- ISMS-P 샘플 모듈을 처음부터 끝까지 학습 가능
- 새로고침·재로그인 후 진도 유지
- 다른 사용자의 진도 접근 차단

### 4단계: 문제은행, 채점, 오답복습

목표: 문제 풀이에서 복습 일정 생성까지 한 흐름을 완성한다.

작업:

- 문제·선택지·과정 매핑
- 문제 세션과 답안 제출
- 서버 측 채점
- 해설과 결과
- 오답 노트와 복습 일정

완료 조건:

- 정답 정보가 제출 전 클라이언트에 노출되지 않음
- 중복 제출·재시도 규칙이 정의됨
- 과정별 정확도와 오답 목록이 계산됨

### 5단계: 관리자 콘텐츠 운영

목표: 개발자 개입 없이 콘텐츠를 작성·검수·발행한다.

작업:

- 콘텐츠·문제 CRUD
- 초안, 검수, 발행 상태
- 과정·분류 매핑
- 변경 이력과 감사로그
- 입력 검증과 위험한 HTML 처리 정책

완료 조건:

- 권한 없는 사용자 쓰기 차단
- 발행 중인 학습 콘텐츠 버전 안정성 보장
- 중요 변경을 행위자와 시각 기준으로 추적 가능

### 6단계: 시험과 분석

목표: 과정별 모의평가와 학습 분석을 제공한다.

작업:

- 시험 구성과 문제 배정
- 제한시간, 제출, 점수
- 과정·영역별 분석
- 최근 추이
- 약점 기반 규칙형 추천

완료 조건:

- 시험 중 콘텐츠 버전이 고정됨
- 점수 재계산 가능
- 사용자별 과정 데이터가 섞이지 않음

### 7단계: 콘텐츠 확장

목표: ISMS-P에서 검증한 엔진을 나머지 6개 과정으로 확장한다.

순서 제안:

1. CPPG 개인정보관리사
2. 개인정보 영향평가
3. 정보보안기사
4. 정보보안산업기사
5. 정보보호위험관리사(ISRM)
6. SW 보안약점 진단원

이 순서는 콘텐츠 공통성에 따른 제안이며 공식 우선순위가 아니다.

완료 조건:

- 과정별 분류체계가 데이터로 구성됨
- 공통 콘텐츠가 중복 없이 매핑됨
- 과정별 진도·평가 통계가 분리됨

### 8단계: 운영 보안과 출시 준비

목표: 실제 사용자 데이터를 다룰 수 있는 운영 기준을 만족한다.

작업:

- CSP와 보안 헤더
- rate limit과 남용 방지
- 개인정보 보유·파기
- 관리자 최소권한과 정기 검토
- 백업·복구·마이그레이션 절차
- 접근성, 성능, 모바일 E2E
- 의존성 취약점 감사
- 운영 모니터링과 장애 대응 절차

## 구현 우선순위

| 우선순위 | 범위 | 이유 |
|---|---|---|
| P0 | 빌드 기준선, 과정 모델, 과정 전환 | 이후 모든 데이터의 범위를 결정 |
| P0 | 인증 적용과 서버 권한 | 사용자 데이터 저장 전 필수 |
| P1 | 콘텐츠와 진도 | 학습 플랫폼의 첫 사용자 가치 |
| P1 | 문제·채점·복습 | 핵심 반복 학습 루프 |
| P2 | 관리자 운영 | 콘텐츠 규모 확대 전 필요 |
| P2 | 시험·분석 | 데이터 축적 후 가치 증가 |
| P3 | AI 추천·고급 자동화 | 규칙 기반 기능 안정화 후 도입 |

| 롤백 불가 | Git 기준선과 마이그레이션 롤백/전진복구 절차 마련 |
