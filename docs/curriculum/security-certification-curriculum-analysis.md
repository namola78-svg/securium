### 현재 분석 한계

현재 실행 환경에는 PDF 텍스트 추출 도구(`pdftotext`, `pypdf`, `pdfplumber`, `fitz`)가 없고, 네트워크 제한으로 Python PDF 라이브러리 설치도 실패했다. 브라우저에서 로컬 PDF를 직접 여는 방식은 보안 정책으로 차단되었다.

따라서 이번 문서는 공식 웹 페이지에서 확인 가능한 고수준 시험 구조를 확정 사실로 기록하고, PDF 내부 표의 주요항목·세부항목·세세항목·수행준거는 “문서 원문 확인 필요”로 구분한다. 공식 PDF에 없는 세부 항목을 임의로 생성하지 않는다.

## 2. 현재 저장소 구조 요약

### 확인한 주요 모델

| 모델 | 역할 | 주요 제약 |
| --- | --- | --- |
| `courses` | 과정 | `code`, `slug` unique |
| `subjects` | 기존 과정별 과목 | `course_id + code` unique |
| `topics` | 기존 과목별 주제 | `subject_id + code` unique, self-reference 가능 |
| `curriculum_trees` | 과정별 공식/버전 커리큘럼 트리 | `course_id + version` unique, 과정별 ACTIVE tree 단일 unique |
| `curriculum_nodes` | 트리 내 계층 노드 | self-reference `parent_id`, depth 0~20, metadata JSON 길이 제한 |
| `contents` | 공유 학습 콘텐츠 | `slug`, `canonical_key` unique |
| `course_lessons` | 과정별 콘텐츠 제공 브리지 | `course_id + curriculum_node_id + content_id` unique |
| `user_course_lesson_progress` | CourseLesson 기준 사용자 진도 | `user_id + course_id + course_lesson_id` unique |

### 확인한 과정

| 자격 | course id | code | slug |
| --- | --- | --- | --- |
| 정보보안기사 | `course-ise` | `ISE` | `information-security-engineer` |
| 정보보안산업기사 | `course-isie` | `ISIE` | `information-security-industrial-engineer` |

### 기존 Seed와 공식 기준의 차이

현재 `db/seed.sql`의 정보보안기사·정보보안산업기사 Subject/Topic은 공식 출제기준 기반이 아니라 모든 과정에 공통 생성되는 샘플 구조다.

현재 샘플 Subject 템플릿:

- `FOUNDATION`
- `PRACTICE`
- `REVIEW`

공식 출제기준 기반 구조는 기존 샘플 Subject/Topic을 즉시 삭제하지 않고 `curriculum_trees` / `curriculum_nodes`에 별도 tree로 추가하는 것이 안전하다. 기존 학습 기록과 CourseLesson 연결을 보존해야 하기 때문이다.

```text
│  ├─ 시스템보안
│  │  └─ 주요항목
│  │     └─ 세부항목
│  │        └─ 세세항목
│  ├─ 네트워크보안
│  ├─ 어플리케이션보안
│  └─ 정보보안일반
└─ 실기
   └─ 정보보안 실무
      └─ 주요항목
         └─ 세부항목
            └─ 세세항목 또는 수행준거
```

실제 PDF 세부 구조가 위 초안과 다르면 PDF 원문 구조를 우선한다.

## 8. Node Type 정책

### 현재 enum

`lib/validation.ts`의 `curriculumNodeTypes`:

- `TRACK`
- `SUBJECT`
- `DOMAIN`
- `MAJOR_ITEM`
- `SUB_ITEM`
- `STANDARD`
- `LIFECYCLE`
- `PRACTICAL`
- `MODULE`
- `CHAPTER`
- `CUSTOM`

### 권장 매핑

| 공식 문서 계층 | 권장 nodeType | 보조 metadata |
| --- | --- | --- |
| 필기/실기 구분 | `TRACK` | `examType: WRITTEN/PRACTICAL` |
| 필기 과목 | `SUBJECT` | `officialLevel: SUBJECT` |
| 실기 영역 | `PRACTICAL` 또는 `DOMAIN` | `officialLevel: PRACTICAL_DOMAIN` |
| 주요항목 | `MAJOR_ITEM` | `officialLevel: MAJOR_ITEM` |
| 세부항목 | `SUB_ITEM` | `officialLevel: SUB_ITEM` |
| 세세항목 | `STANDARD` 또는 `CUSTOM` | `officialLevel: DETAIL_ITEM` |
| 수행준거 | `STANDARD` 또는 `CUSTOM` | `officialLevel: PERFORMANCE_CRITERION` |

초기 구현에서는 enum을 추가하지 않고, 공식 계층명은 `metadata.officialLevel`로 보존하는 방식이 안전하다.

## 9. Stable Key 정책

### Tree key

| 자격 | 권장 tree id | version |
| --- | --- | --- |
| 정보보안기사 | `curriculum-ise-2023-2026-official` | `2023-2026` |
| 정보보안산업기사 | `curriculum-isie-2023-2026-official` | `2023-2026` |

### Node key

권장 형식:

```text
{COURSE_CODE}-{VERSION}-{EXAM_TYPE}-{SUBJECT_ORDER}-{MAJOR_ORDER}-{SUB_ORDER}-{DETAIL_ORDER}
```

예:

```text
ISE-2023-2026-W
ISE-2023-2026-W-01
ISE-2023-2026-W-01-01
ISE-2023-2026-W-01-01-01
ISE-2023-2026-P
ISE-2023-2026-P-01

ISIE-2023-2026-W
ISIE-2023-2026-W-01
ISIE-2023-2026-W-01-01
ISIE-2023-2026-P
ISIE-2023-2026-P-01
```

현재 `curriculum_nodes`에는 전용 stable key 컬럼이 없으므로 다음 중 하나를 선택해야 한다.

1. 단기: `officialCode`에 stable key 저장
2. 중기: `stableKey` 컬럼 추가

단기 구현에서는 기존 schema를 활용하기 위해 `officialCode` 사용을 권장한다. 다만 공식 문서의 원래 코드가 따로 존재하는 경우 `officialCode`와 stable key의 의미가 섞일 수 있으므로, 중장기적으로는 `stableKey` 컬럼 추가가 더 명확하다.

## 10. Metadata 정책

`curriculum_nodes.metadata`에 다음 정보를 저장하는 것을 권장한다.

```json
{
  "source": "KCA_CQ",
  "sourceDocument": "정보보안기사 출제기준.pdf",
  "sourceUrl": "https://www.cq.or.kr/qh_cusgm10_002.do?bbscttNo=65",
  "effectiveFrom": "2023-01-01",
  "effectiveTo": "2026-12-31",
  "examType": "WRITTEN",
  "officialLevel": "SUBJECT",
  "officialPage": null,
  "confirmedFromPdf": false,
  "needsPdfVerification": true,
  "sampleOnly": false
}
```

원문 확인 전에는 `confirmedFromPdf: false`, `needsPdfVerification: true`를 유지해야 한다.

## 11. Subject/Topic 호환성 정책

`subjects` / `topics`는 기존 학습 화면과 문제 필터에서 이미 사용된다. 공식 출제기준 구조를 `curriculum_nodes`로 도입하더라도 기존 Subject/Topic을 즉시 제거하지 않는다.

권장 단계:

1. 공식 `CurriculumTree`를 `DRAFT`로 생성
2. 공식 node와 기존 Subject/Topic 간 매핑 검토
3. 공유 콘텐츠는 `contents` / `course_lessons`로 연결
4. 공식 Tree 검증 후 `ACTIVE` 전환
5. 기존 샘플 Subject/Topic은 학습 기록 영향 분석 후 보관 또는 비활성화 검토

## 12. Migration 필요성

현재 공식 출제기준 Tree를 담는 데 신규 테이블은 필요하지 않다. `curriculum_trees`와 `curriculum_nodes`가 이미 존재하기 때문이다.

다만 다음 개선은 후속 단계에서 검토할 수 있다.

| 후보 | 필요성 | 이번 단계 판단 |
| --- | --- | --- |
| `curriculum_nodes.stable_key` | 공식 문서 코드와 내부 안정 키 분리 | 선택 사항 |
| `curriculum_nodes.source_page` | 원문 페이지 추적 | metadata로 대체 가능 |
| `curriculum_nodes.source_line` | 원문 줄/표 위치 추적 | PDF 구조 확인 후 판단 |
| `curriculum_nodes.confirmed_from_pdf` | 검증 상태 검색 최적화 | metadata로 대체 가능 |

이번 단계에서는 destructive migration이 필요하지 않다.

## 13. 후속 Seed 설계 방향

후속 Seed는 다음 순서로 작성한다.

1. `curriculum_trees`에 기사/산업기사 공식 tree를 각각 생성
2. `curriculum_nodes`에 필기/실기 TRACK 노드 생성
3. 필기 과목 SUBJECT 노드 생성
4. PDF 원문에서 확인한 주요항목/세부항목/세세항목을 하위 노드로 생성
5. 실기 영역과 수행준거를 PRACTICAL 또는 DOMAIN 하위 노드로 생성
6. `course_lessons`는 기존 공유 콘텐츠를 공식 node에 연결하는 방식으로 점진 전환

공식 PDF의 세부 항목이 확인되기 전에는 주요항목 이하를 임의 생성하지 않는다.

## 14. 확인하지 못한 항목

- 정보보안기사 필기 각 과목의 주요항목, 세부항목, 세세항목
- 정보보안기사 실기 영역의 주요항목, 세부항목, 수행준거
- 정보보안산업기사 필기 각 과목의 주요항목, 세부항목, 세세항목
- 정보보안산업기사 실기 영역의 주요항목, 세부항목, 수행준거
- PDF 내부 표의 페이지 번호
- PDF 내부 공식 코드 체계 존재 여부
- 과목명이 같은 영역의 기사/산업기사 세부 범위 차이

## 15. 최종 판단

현재 저장소에는 공식 출제기준을 수용할 수 있는 `curriculum_trees`와 `curriculum_nodes` 구조가 이미 구현되어 있다. 또한 `CourseLesson` 기반 구조가 있어 공식 노드와 공유 학습 콘텐츠를 후속 단계에서 연결할 수 있다.

다만 현재 개발 Seed의 Subject/Topic은 공식 출제기준 기반이 아니며, 공식 PDF 내부 세부 표를 아직 텍스트로 추출하지 못했다. 따라서 다음 구현 단계로 바로 공식 세부 노드 Seed를 만들기보다는 PDF 원문 표를 텍스트, Excel, 이미지 OCR, 또는 설치 가능한 PDF 추출 도구로 먼저 확보해야 한다.
